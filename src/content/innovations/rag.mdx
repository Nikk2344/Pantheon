## Two places to store information

A model's parameters encode patterns learned during training. A document index stores passages that can be retrieved at inference time. The 2020 RAG work combined these forms of memory and studied open-domain question answering and other knowledge-intensive tasks.

Its original design used a dense retriever and a pretrained sequence-to-sequence generator. The authors explored variants that condition on retrieved documents differently during generation. The term RAG now covers a broader family of pipelines; not every application implements that original training procedure.

## Work through a library question

Suppose a reader asks when a museum changed its opening hours. A model trained earlier might not know. A retrieval system could fetch the current schedule, allowing the answer to use newer information without retraining all model weights. This is an illustrative workflow, not a claim that a particular system can access live schedules.

Now imagine the index contains an old schedule and a new one. Both match the question. Retrieval has found relevant text, but the application must still resolve the dates. If it cites the new page while copying hours from the old page, the presence of a citation has not solved the error.

## Evaluate the stages separately

First test whether the needed evidence is present in the index. Then test whether retrieval finds it. Finally test whether the answer uses it accurately and admits when evidence is insufficient. Collapsing these stages into one answer score can conceal the source of failure.

For a reading exercise, compare a generated answer with each cited passage. Mark which sentences are directly supported, which require inference, and which have no support in the retrieved material.
